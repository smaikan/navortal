# MVP-14 — somut manuel plan sözleşmesi

Durum: MVP-14 uygulandı ve kabulü geçti. Kanıt docs/verification/mvp-14.md içindedir. Bu dosya somut mimari/API kararını açıklar. SchedulingEngine henüz yazılmayacak; aynı revision writer sonraki motor apply akışında kullanılacak.

1. DailyPlan owner/localDate unique ve frozen IANA zone taşır. GET eksik günü varsayılan boş context olarak okur, DB yazmaz. İlk mutation revision1 oluşturur; ilk Work içeren kabul baseline olur. Current/baseline aynı planın revision'ına compositeFK ile bağlıdır.
2. TaskSchedule kalıcı kimlik, owner/plan/task, Work/Break/Buffer, UTC start/end, fixed/locked, Planned/Removed, split group/origin ve creation metadata snapshot taşır. Work yalnız gerçek own component'e aittir; Break/Buffer task taşımaz. Remove soft'tur. Task kimliği blok üzerinde değiştirilmez.
3. Her kabul current+full active snapshot+changes+PlanningVersion+idempotency aynı kısa user transaction'ında yazılır. Removed kayıt snapshot'ta etkin blok değildir; çıkarma before/after Changes'te ve önceki item'larda korunur. Çok günlük gece bölünmesi tek ChangeSet'tir. Revision önceki revision'a bağlanır; Number plan.Version'dır.
4. Metadata blok oluşturulurken task adı/yol/grup/estimate/state olarak dondurulur; task rename eski blok ve revision'ı rewrite etmez. Canlı task ayrıntısı ayrı task endpointinden gelir. Work start kendi actual-start snapshot'ını ayrıca tutar.
5. Create {localDate,taskId?,kind,startsAt,endsAt,isFixed,isLocked,allowConflicts,expectedPlanningVersion,reason?}; Idempotency-Key gerekli. Zamanlar explicit instant; localDate seçilen plan günüdür. Yeni plan zone'u tercihten, mevcut gün kendi frozen zone'undan gelir. Geceyi geçen range gün sınırlarında bağlı parçalara ayrılır; en çok7gün, bir komutta en çok8gün. Komşu tarih zaten farklı zone'a sahipse açık conflict; sessiz redate yok.
6. PUT /api/schedules/{id} {version,expectedPlanningVersion,startsAt,endsAt,isFixed,isLocked,allowConflicts,allowProtectedChange,reason?} aynı yerel gün içinde update eder. Başka güne move MVP-20'nin ayrı atomik niyetidir. Gece parçaları kalıcı ayrı kimliktir. Fixed/locked elle değişiklik açık allowProtectedChange ister.
7. POST /{id}/remove aynı sürüm/kullanıcı niyetini kullanır. Manuel overlap default409, allowConflicts=true ise warning+revision change bağlamında açık kabul edilir. Break/buffer actual üretmez. Geçmişte plan değişikliği yeni revision'dır; actual'a dokunmaz.
8. GET /api/daily-plans/{date}, GET /api/schedules?from&to&offset&limit ve revision list/detail/items/changes owner kapsamlı/bounded. UTC aralık en çok366gün. Work planned/unplanned filtreleri aynı TaskId'nin seçilen gelecek horizon'unda aktif rezervasyonlarıdır; actual/remaining'den ayrı miktardır.
9. Planned start taskId+scheduleId+scheduleVersion alır; aynı user/task Work block ve güncel revision item sunucuda doğrulanır. StartedScheduleId ve StartedRevisionItemId o anda bağlanır. Sonraki move/remove bağı yeniden yazmaz. FK'ler owner/schedule/item/task eşleşmesini korur; nullable task principal key zorlaması yerine task eşleşmesi gereken DB constraint'i açık migration SQL ile sağlanır.
10. Task complete/direct/subtree/defer/skip/cancel/archive gelecekteki ilgili Work bloklarını aynı transaction'da kaldırır. Şimdi içindeki blok now'a kısalır; geçmiş bölüm ve eski revision korunur. ParentOnly açık çocuk rezervasyonlarını silmez. Reopen eski planı kendiliğinden restore etmez. Gelecek rezervasyon varken own component container'a çevrilemez.

İç uygulama sırası: A) UTC gün bölme+entity/FK/snapshot writer, B) manuel HTTP+read+idempotency, C) work/lifecycle/filter bağlantıları, D) clean/upgrade/race/rollback ve milestone kabulü. Kapanış bütün M14 iş/kabul kapıları geçince yapılır.
